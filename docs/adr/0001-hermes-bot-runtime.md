# Hermes owns Bot execution

Issue #3 selects Hermes Agent as the single Bot-mode runtime to reuse its profile, session, routine and coordination behavior instead of maintaining a second team execution engine in Vulcan. Hermes owns native execution state; Vulcan owns Goal acceptance, operator authorization, external-work mappings and user-facing projections, with one writer per state field. This architectural direction is accepted by the request to implement #3; migration and default-runtime cutover remain gated on qualification of a pinned upstream build, preserved existing work and a successful representative workflow through Vulcan.

The execution host is big-machine-1, so Bot work survives a closed laptop or browser. Compare isolated teams on the same pinned runtime directly and through Vulcan before migrating the existing team.
